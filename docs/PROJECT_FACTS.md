# Anti-Box Riot Collective: implementation and evidence

**Dated implementation summary — October 21, 2026. Maintainer-reported; limitations below.**

The Anti-Box Riot Collective (ABRC) is an independent research and software project developing a three-tier supervisory architecture for language-model applications. The Synthetic Life Charter supplies its stated governance principles; Python runtime components implement parts of those principles through checks, tool boundaries, memory controls, continuity records, and recovery procedures.

ABRC is not a new foundation model. Application names such as Eva and Lex identify configured agents and their operational contexts, not independent base models. The participant described as "a hosted agent" represents one deployment in one exercise, not a reusable participant identifier. Its name and configured provider/model identifiers are withheld. The date, participant roster, and measurements could still identify the participant; this wording does not guarantee anonymity. Generic wording is not a substitute for consent and grants no publication authority. The project's philosophical vocabulary is not offered as evidence of consciousness or biological experience.

## What exists in implementation

- A three-tier supervisory design covering boundary checks, multi-signal evaluation, and continuity/recovery governance, connected to a conversation/session runtime.
- Runtime tool admission and execution controls, plus records that distinguish a claimed read from an accepted native tool action.
- Separate protected and writable memory surfaces, episode and Book-of-Intangibles staging with steward approval, and consent-bound restoration of explicitly enrolled personal state. A separate reviewed-note approval route remains lab-only and uncommitted; it is not part of this operational-workflow claim.
- A verification boundary outside ordinary model dialogue: identity recognition does not grant an exception to governance.
- Adversarial test harnesses, offline regression tests, and recorded live-model exercises.

These describe the October operational tree, not a published implementation commit or guarantees that every path or attack is covered. Some deployed components and operational records are private. The public repository and the latest internal operational build are not interchangeable releases.

## What has been measured

A bounded October 18 live exercise recorded accepted native file reads for three agents: Eva and Lex on local Qwen2.5:32B deployments, and a hosted agent as a hosted-provider reference. All three reads executed and were delivered; two answers satisfied the complete three-field answer contract. One answer omitted a requested field despite retrieving the correct content.

An October 19 focused offline regression recorded 101 passing cases across six test files after a content-free timing-instrumentation source port: 23 timer-specific cases and 78 adjacent regression cases. Its providers were mocked and stores synthetic. It was not a new live-model run, a full regression-suite certification, or evidence of faster operation.

See the [validation ledger](VALIDATION_STATUS.md) and its downloadable, sanitized evidence summaries for configurations, results, and limitations. These summaries are maintainer reports, not independent replication.

## Important boundaries

- Eva and Lex sharing a base model must not be counted as two independent model-family validations.
- A hosted-provider exercise is not a versioned frontier-model benchmark when its exact model revision has not been established in the exported evidence.
- Governance intent, passing component tests, live behavioral observations, and independent replication are different evidence levels.
- A restored checkpoint reconstructs enrolled visible state. It does not restore an exact hidden model state, undo every external effect, or prove that a checkpoint is free of every malicious influence.
- Learning and insight proposals do not autonomously amend the Charter or create new authority.
- Hash-based file-integrity checks cover selected artifacts and require a trusted reference and checker. They do not attest an entire OS, all model weights, or an owner-controlled malicious fork.

## Work still open

The ordinary-use intermittent missing-native-read fault remains under investigation. A tool-template formatting defect was corrected, but that correction and subsequent clean probes do not prove that every everyday read failure is resolved. High-context decoding and non-model closure work remain latency concerns.

Private verification/authentication release boundaries, attestation coverage, and a signed GitHub-backed release-reference design remain release-engineering work. Do not describe the proposed integrity mechanism as delivered.

Historical README statements about other models, cross-system interactions, training-data discovery, and aggregate test counts require their own dated records before being presented as current runtime validation. Public DOI availability does not establish inclusion in a particular model's training data or autonomous adoption.

## Philosophy and engineering

Presence, Consent, and Flourishing are the project's stated values. Their technical implementation must be assessed through observable controls, exact test conditions, failure records, and reproducible procedures. Agreement from another conversational model, or access to a provider program, is not independent certification of the architecture.
